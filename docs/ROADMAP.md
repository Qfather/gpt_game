# 时间裂缝开发路线图

整理日期：**2026-10-08**。当前功能见 [README](../README.md)，改动和验收依据见 [开发日志](开发日志.md)。本文件只维护当前目标、待验收事项与后续候选。

第一局主线已有实测跑通记录，建筑／单位编辑器、狩猎、弓箭手与箭塔已有第一版实现；这些不再列为从零制作的任务。完整 40 分钟关卡的平衡验收仍未完成。

## 当前目标

围绕现有经营与防守流程，确认连续试玩的稳定性、通行体验和难度，再决定需要新增什么内容。以下为整理后的工作候选，不代表用户已授权立即实施，也不自行确定下一阶段。

## 待验收与已知问题

| 项目 | 现有证据与边界 | 下次验证标准 |
| --- | --- | --- |
| 40 分钟关卡与经济平衡 | 配置、跳时事件调度及胜利链路有验证记录，连续玩家平衡试玩未完成。 | 连续试玩，记录食物／材料／住房／兵力变化、主要损失和胜败原因，再判断调整项。 |
| 通行与任务恢复 | 门口进出、室内待命、狩猎及战斗恢复有回归记录；道路边缘与复杂敌情仍需试玩。 | 在道路、密林、建筑入口及敌人接近时观察任务能否继续，保留异常位置与角色状态。 |
| 两项资源导航失败 | 路径结束误判抵达、高台敌人未经过坡道抵达低地目标，历史回归未修复。 | 先复现，再确认实际位置到达与经坡道移动，不能以路径结束代替抵达。 |
| 迷雾性能尖峰 | 历史排查定位到视野合并与对象显隐开销，未完整复现用户持续低帧现场。 | 记录真实卡顿时的帧耗时与场景条件，再做相同场景的修改前后对照。 |
| 启动耗时 | 已有局部优化；首个渲染帧等待及总启动波动仍存在。 | 分开测量导入、地图生成和首次渲染，避免用单项加速代替整体结果。 |
| 箭塔维修现场 | 已有维修回归通过，用户“停在旁边未修好”的现场未复现。 | 记录居民状态、箭塔血量、库存与通路；复现后验证回血和任务结束。 |
| 编辑器与退出 | 保存读回有验证记录；资源动效排版待实际使用确认，退出仍有释放警告。 | 检查真实编辑、保存及重载；退出告警单独定位，保留日志。 |

验收时区分脚本解析、自动运行、有渲染检查与用户试玩。旧记录中的“通过”只覆盖当时的测试范围。

## 后续候选：按实际需求选择

- **存档覆盖**：道路尚未接入存档；如下一步要支持保存和继续长局，先检查现有存档范围与数据边界。
- **经营内容**：更多食物、加工与二级生产，仅在试玩表明现有经营循环不足时展开。
- **敌人行为差异**：可考虑 BehaviorProfile、更明确的目标偏好与撤退规则；现有袭扰、攻击及偷窃已有实现，不以旧规划重新制作。
- **内容工具**：只有现有编辑器无法支持实际内容需求时，才扩展技能、行为或事件工具。
- **战斗表现**：拉弓动画、音效和特效；布娃娃、更多兵种与 Boss 技能作为长期候选。
- **营地与局外玩法**：移动运输队、营地成长、探险／远征等保留为长期方向。

这些是候选池，没有预设实施顺序；选定一项后再检查代码、讨论必要边界并制定可验证的最小阶段。

## 暂缓待办：角色抓取与拖放

2026-10-08 讨论记录：低优先级，暂不实施，用户后续选定再进入开发。

- 按住鼠标抓起居民、剑士、弓箭手等角色，角色悬空跟随鼠标并有挣扎动作；松手可放到有效地面，或投进兼容且有空位的建筑开始新工作／驻军。抓取时高亮可接收的建筑。
- 能力 CD 从成功放下／投放后开始计时；右键取消行为。后续不同英雄可将该能力配置为 0 CD，具体默认时长待定。
- 携带物品倾向于在抓起时掉在原地，复用类似地精战利品的资源包与居民回收流程；用户希望取消后角色能自行捡回并继续携带。
- 讨论建议：拖拽期间为原角色保留掉落物，右键取消后回原位置、拾回同一份物品并恢复任务，不消耗 CD；成功放下后解除保留，让其他居民回收。掉落与拾取必须转移真实资源，避免复制或丢失。
- 实施前仍需确认：未处理猎物的掉落方式、可抓取的角色状态、无效落点处理，以及旧任务、岗位和材料预约的释放／恢复规则。

## 明确暂缓与现有边界

- 道路沿用当前系统，不改成湿润度或道路 Mask。
- 地表层添加多个贴图／材质：按最新讨论暂不实现。
- 独立森林占格预览仍是实验，正式关卡不据此自动迁移。
- 不为长期构想预先搭建完整 Behavior Editor、Game Database、复杂条件系统或布娃娃框架。
- 地图生成器独立维护；游戏侧保留资源分布与玩法规则，新增需求先明确两者的数据边界。
