# 瞭望塔警戒与居民避险

实现日期：2026-10-08。

## 使用与默认参数

战略建筑菜单新增瞭望塔，占地2×2，木材20，施工15秒，最多2人施工，血量300。建筑完成后，详情面板点击“安排值班”，最多安排1名居民。居民先走到正面，再沿梯子进入平台，模型在塔上保持可见；选中建筑显示水平20米圆形范围。

只有实际登塔并进入值班状态后才有警戒效果。进食、休息、撤岗、取消工作、拆除或被摧毁时暂停；进食休息后回岗恢复。塔搬迁时平台上的居民随塔移动。值班者受到建筑保护，登塔后不占用地面碰撞。

## 警报与避险

- 聚落警报统一每0.2真实秒检查一次，不随3倍速重复放大。任意有效瞭望塔发现水平半径内的存活敌方单位即报警，敌人离开后保持2秒安全延迟。
- 非战斗居民不再各自扫描敌人；警报期间，未受城墙保护者固定回自己的住所，无有效住所则回据点。保留工作岗位，解除警报后恢复工作。
- 已经回到屋内的居民等待警报解除再外出，不会因为房屋位于墙内就反复进出。
- 没有有效塔警报时，仅实际受击的普通居民触发避险；先至少避险5秒，已知攻击者仍在附近时继续避险。战斗单位保留战斗逻辑，值班居民留在塔上。

## 城墙保护

仅完工、存活、登记网格的墙、城门和墙上塔楼参与判断。四向连接中的完整闭环围合内部区域，端点与断墙剔除；高低差超过0.1米断开，城门须沿对应轴向连接，对角漏缝不算封闭。

墙体变化才重建围合缓存，居民直接查询结果。敌人位于某围合区内部时，该区域暂不提供警报豁免；离开后恢复。居民即使在保护区内，受到攻击仍会避险。

城门目前保留通道、没有开关状态，本轮按完整城门参与围合。这是避险判断规则，不能当作城门已经可以阻挡敌人的验证。

## 场景与验证

场景：`Scene/building/game/watchtower.tscn`；配置：`data/buildings/WatchtowerData.tres`。现用原生木结构基本体，梯子正面为本地+Z；替换模型时保留 `ImmigrationEntrance`、`ClimbFoot`、`WatchPlatform` 与点击碰撞节点，平台高度由 `WatchPlatform` 决定。场景的 `work_radius` 控制警戒与选中范围，默认20米。

`Tests/watchtower_alarm_test.gd` 覆盖战略菜单、真实登塔、选中范围、边界与阵营、回家避险、无普通居民搜敌、进食回岗、撤岗、取消工作、搬迁及塔被毁撤离；加 `-- --visual` 在有画面的进程记录近景和范围截图。

`Tests/wall_enclosure_alarm_test.gd` 覆盖闭环、缺口、城门轴向、高低差、敌人进入和缓存复用。真实塔上居民与圆形范围已检查渲染截图；连续完整关卡、极端复杂城墙布局和本次规则变更后的大规模帧率仍需单独试玩或压力测试。旧性能报告记录的是旧避险行为，不作为新规则的帧率承诺。
