# 城墙与防线模型配置

石墙、木桩墙、石城门、木城门、石塔楼、木塔楼均已接入建筑配置和底部建造菜单，默认外观使用基本体。

## 建造规则

- 城墙占地 1×1：左键拖拽，预览与提交使用同一条四向绕障路线，绕过建筑、资源与不可建地形；无法连通时显示红色，不能提交。已有墙段和墙工地不重复收费。
- 城门占地 4×1，可用 R 旋转。空地建造全价；对应材质的四格已完工直墙可直接改建，成本减半。三格墙加空地、拐角／三通／四通、正在改建塔楼的墙不能覆盖。
- 拍下城门蓝图立即移除原四墙，施工期间无血量和实体阻挡；取消后留空地。完工城门仍沿用现有可通行规则，开关门尚未实现。
- 塔楼占地 1×1，只能建在对应材质的已完工墙段上。施工保留底墙防御，工人在外侧施工；取消保留底墙，完工才替换。底墙被摧毁则取消工地。塔楼工地不可搬迁。
- 每座塔楼最多驻守一名弓箭手，沿用箭塔的射程、视野及补粮规则。木石墙可互相连接，门与塔楼改建须匹配底墙材质。

## 替换模型

重新加载资源编辑器插件或重启 Godot 后，在建筑编辑器中选择石墙／木桩墙，为六个形态字段分别指定自己的 `PackedScene`：

| 形态 | 默认朝向 |
| --- | --- |
| 独立 | 无连接 |
| 尽头 | 北 |
| 直线 | 北、南 |
| 拐角 | 北、东 |
| 三通 | 北、东、西 |
| 四通 | 北、东、南、西 |

北为 `-Z`，东为 `+X`。场景使用 `Node3D` 根节点，网格放在子节点中；原点为格中心、地面为 `Y=0`，标准一格宽 1 米，连接端延伸到半格边缘。运行时按地图格尺寸缩放 X/Z，并根据同层四邻自动旋转；增删墙段会更新相邻外观。

默认外观位于 `Scene/building/visual/fortifications/`：`stone_wall_*` 与 `wood_wall_*` 各六份。模型只提供外观，碰撞与连接由功能脚本维护。六种引用都必须有效；城墙／塔楼占地固定 1×1，城门固定 4×1，保存时会校验。

城门和塔楼在编辑器的「外观模型」中指定自己的场景，保留功能场景的脚本。默认门模型宽 4 米，塔楼一格宽，弓箭手站位为建筑原点上方 3 米；替换塔楼模型时将平台设在此高度。基础配置中的血量、成本、施工时间仍可调整，目前木石数值为原型初值，尚未做平衡验收。

## 验证入口

`Tests/fortification_system_test.gd` 覆盖正式模型引用、16 种连接、真实鼠标处理、绕障、物理墙段连接、城门改建和取消、塔楼底墙生命周期、单人弓箭手驻军。`Tests/fortification_editor_test.gd` 覆盖字段显示、场景替换、隔离自动保存读回与无效配置拒绝。

系统测试使用小型测试地图；完整聚落的连续运料、施工、战斗与大规模拖拽仍需试玩。截图展示的是正式模型在测试场景中的渲染，不等于完整关卡验收。

`Tests/wall_navigation_test.gd` 在主场景地图中验证三个相连墙段的实体阻挡、移民与敌人实际绕行，以及摧毁和拆除后导航更新。
