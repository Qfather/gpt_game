## 游戏全貌 {#system-overview}

最后核对：2026-10-09。[返回首页](项目.md)

### 玩家在经营什么

玩家经营一个聚落。居民自动采集、运输、施工、生产、吃饭和休息；玩家决定建筑布局、岗位人数、训练与防御投入。军事单位自动迎战、驻军与巡逻，也可由营地面板分配寻宝任务。

有限的劳动力、材料、食物和住房决定发展速度；袭扰与时间裂缝要求把经济转成防守能力。保住据点并完成最后的裂缝 Boss 事件是当前主线胜利条件。

来源：[README](../README.md)、[Boss 胜利条件](归档/BOSS_V0_关卡配置与胜利条件.md)、`Script/world/encounter_director.gd`、`Script/game_state.gd`。这是一份当前流程归纳，不新增规则。

### 一局怎样运转

| 环节 | 输入与行动 | 结果／约束 | 对应系统 |
| --- | --- | --- | --- |
| 基础经营 | 安排木石采集、农舍生产、施工运输 | 资源分布在仓储和居民手中，必须实际交付 | [居民与资源物流](系统.md#system-logistics) |
| 人口增长 | 食物库存、建成建筑、空住房满足移民组要求 | 倒计时、远端生成、实际入住，增加劳动力与需求 | [人口与饮食](系统.md#system-population) |
| 军事发展 | 基础民兵营、材料、居民和本局蓝图 | 训练成为军人；蓝图允许高级兵营分支升级 | [建筑与防线](系统.md#system-buildings) |
| 防守与探索 | 军营、箭塔、墙门、道路、视野 | 自动战斗与警戒，普通居民避险，营地清剿后搬运奖励 | [战斗训练与营地](系统.md#system-combat) |
| 关卡压力 | 袭扰时间线与裂缝倒计时／波次 | 普通压力与主线分别调度；裂缝未清可使后续事件顺延 | [40 分钟关卡原说明](归档/40分钟困难关卡说明.md) |
| 胜败 | 完成最后裂缝 Boss 事件／据点被毁 | 胜利或失败，暂停模拟并显示结果 | `Script/game_state.gd` |

### 为什么这些系统互相牵制

- 更多居民意味着更多生产能力，也需要住房和持续食物。
- 把居民训练成军人会增加防守能力，同时减少普通劳动力。
- 本局蓝图控制进阶建筑权限，解锁后仍要支付材料和施工成本。
- 建筑布局改变入口、道路和防线；导航路线成功不代表角色实际能交互。
- 昼夜与迷雾影响可见范围；警戒范围、射程、迷雾视野是三个不同概念。

依据见对应系统页、[移动约束](归档/移动与导航约束.md)和[箭塔警戒](归档/箭塔警戒与居民避险.md)。

## 居民与资源物流 {#system-logistics}

最后核对：2026-10-09。[首页](项目.md) · [游戏全貌](系统.md#system-overview)

实现状态：基础链路已实现；已有局部运行与渲染记录，通行和用户现场仍有未收口项。本轮检查代码与资料，没有重新运行游戏。

### 居民怎样工作

普通居民按岗位和任务行动：伐木、采石、农场、猎人岗位，以及公共搬运、施工和维修。岗位配置决定人数、工作范围与生产内容；任务系统负责认领、取消、完成和材料预约。空闲人口不能把正在睡觉、军事职责或仍在交接的人全部当作可用工人。

| 流程 | 当前规则 | 实现来源 |
| --- | --- | --- |
| 采集 | 找成熟资源、预约目标、实际靠近、采集至携带限制 | `Script/unit/game/villager.gd`、`Script/building/ResourceBuildingBase.gd` |
| 存储与运输 | 回合法入口入屋卸货；工作建筑满仓后运输到据点；不能隔空入库 | `Script/resource/ResourceStorage.gd`、`Script/unit/game/villager.gd` |
| 农业 | 田地生长与采收、农舍岗位派工，粮食进入仓储 | `Script/building/game/farm.gd`、`farm_field.gd` |
| 狩猎 | 独占认领、射杀、实际拾取；最多携带三只，回屋处理后才变成肉 | `Script/unit/hunting_behavior.gd`、[狩猎说明](归档/狩猎与远程_第一版说明.md) |
| 工地 | 材料运输与施工分开；到合法交互位置后交料／累计施工 | `Script/task_manager.gd`、`Script/construction_site.gd` |
| 维修 | 受损建筑产生劳动任务，搬材料并恢复实际耐久 | `Script/task_manager.gd::create_repair_task()`、[历史维修记录](归档/历史记录/开发记录_截至2026-10-07.md) |

默认携带容量等数值可由单位配置修改，不把旧文档里的数值当作永久规则。猎物只数上限与最终肉量是不同单位；未处理猎物不能按肉计入库存。

### 怎样理解资源数字

`ResourceManager` 分别提供仓储、居民携带和总量查询。HUD 总量不能简单当作据点能立即支出的库存；具体扣款、运输与移民检查应追踪各自查询口径。

资源定义使用稳定 ID，例如 `wood`、`stone`。中文名称用于显示，不能当作材料字典键。资源编辑器定义“资源是什么”；关卡配置决定资源投放、生长和再生，见[地图页](系统.md#system-world)。

来源：`Script/resource/ResourceManager.gd`、`resource_database.gd`、`Script/task_manager.gd`、[2026-10-05 材料配置记录](归档/历史记录/开发记录_截至2026-10-07.md)。

### 工作与生活中断

居民有饥饿、疲劳、进食、固定住所休息和待命流程。据点室外空地不足时可排队进入室内待命；室内待命能接任务并出门，睡觉期间不接任务。没有工作资源时等待并按间隔／资源事件重新检查。

辞职、任务取消、死亡或建筑失效必须处理已有货物、目标认领、材料预约和岗位；恢复时还要确认旧任务仍有效。猎户离岗时已有猎物与肉的交接遵循当前狩猎流程，不凭空变成普通居民后丢掉货物。

来源：`Script/unit/game/villager.gd`、`Script/unit/hunting_behavior.gd`、`Script/unit/settlement_idle_space.gd`、[历史进出屋记录](归档/历史记录/开发记录_截至2026-10-07.md)、[移动约束](归档/移动与导航约束.md)。

## 建筑与防线 {#system-buildings}

最后核对：2026-10-09。[返回首页](项目.md)

实现状态：建造、搬迁、维修、防线和首批 T0/T1 蓝图升级已有实现与局部验证；完整关卡和更广泛建筑升级仍未验收。

### 建筑的三个层次

- `BuildingData`：名称、稳定 ID、类别、占地、成本、时间、耐久、外观、蓝图和训练配置。
- 功能场景与脚本：岗位、生产、驻军、入口、碰撞及运行状态。
- 外观场景：模型和材质。替换外观不等于替换建筑业务逻辑。

来源：`Script/building_data.gd`、`Script/building/BuildingBase.gd`、[建筑编辑器说明](归档/建筑编辑器_第一版说明.md)。编辑器后续扩展见[工具页](系统.md#system-tools)。

### 基础建造流程

网格预览与占地检查 → 放置蓝图 → 运料与清障 → 实际到场施工 → 成品接管占地、碰撞与功能。未开工蓝图可免费搬迁；开工后锁定至建成。普通搬迁与拆除规则以现有配置和实现为准。

暂停时玩家操作立即修改实际数据并刷新 UI；角色移动、生产、训练和施工进度仍暂停。朝向提示为贴地三角形，底边沿建筑正面同宽，顶点向前 0.3 米；城墙不显示施工方向箭头。

来源：`Script/build_grid.gd`、`Script/construction_site.gd`、`Script/main.gd`、[开发日志](参考.md#archives)、[README 操作](../README.md)。

### 当前建筑解锁

| 等级／类别 | 内容 | 获得与使用方式 |
| --- | --- | --- |
| T0 | 伐木场、采石场、农舍、民兵营、住宅 | 开局可建 |
| T1 直接建造 | 猎人小屋、军营、箭塔 | 本局获得对应蓝图后建造 |
| T1 原地升级 | 剑士营、弓箭手营 | 获得蓝图后从具体民兵营选择分支 |
| 特殊旧规则 | 道路、火把、木制防线 | 沿用现有规则，不强塞进兵营进化树 |
| 石制防线 | 石墙、石门、石塔楼 | 木制补材料差价升级，不直接加入菜单 |

蓝图本局可重复使用，不是免费建筑或一次性建造券；新局重置。前置关联控制蓝图池与实际升级来源，不要求地图上已建成前置建筑才入池。调试 HUD 有三选一，关闭重开保留本组选项；正式奖励触发、掉率、局外解锁与存档未接入。

来源：[建筑蓝图与公共训练](归档/建筑蓝图与公共训练.md)、`Script/building_catalog.gd`、`Script/ui/hud.gd`、`data/buildings/`。T2/T3 字段可配置，不等于已制作正式高级兵种。

### 分支升级怎样发生

公共训练营按配置列出直接子级。升级前检查权限、费用、合法占地，以及没有训练、室内人员或门口队列；升级期间拒绝新训练、搬迁和拆除源建筑。实际运料施工后替换这座建筑，保留生命比例、朝向、镜像与占地；已训练军人不自动变兵种。

本版原地分支升级用于公共训练营。生产建筑或驻军建筑的库存、工人和驻军迁移没有被统一扩展，不能把配置树称为“所有建筑通用进化已经完成”。来源：`Script/building_catalog.gd::validate()`、[蓝图说明](归档/建筑蓝图与公共训练.md)。

### 墙、门和墙上塔楼

- 墙为 1×1，按四邻连接选择六种形态，可拖拽铺设。阻挡资源允许先放蓝图，工人到场后每个资源固定 5 游戏秒清除，无资源收益，再按原施工时长建造。
- 城门为 4×1。对应四格已完工直墙可半价改建；提交蓝图移除原墙，施工可通行，取消留下空地。城门开关未实现。
- 墙上塔楼只能建在匹配材质的已完工墙上；施工和取消保留底墙，完工替换，底墙被毁取消工地。单塔一名弓箭手。
- 木制升级石制按各材料正差收费，取消保留原建筑；塔楼保留驻军与军粮。完整墙体闭环保护与真实挡敌不是同一判定。

模型正面、六形态朝向、尺寸与替换入口见[城墙模型配置](归档/城墙与防线模型配置.md)。该原文“石制直接建造”和“资源绕过不清障”的描述已被后续规则取代；以上现状来自[开发日志](参考.md#archives)、[工程约束](../AGENTS.md)及当前配置。

## 人口与饮食 {#system-population}

最后核对：2026-10-09。[返回首页](项目.md)

实现状态：住房、阶段移民、需求刷新、真实入住和饮食喜好已实现，有已有运行与编辑器验证记录；完整经济平衡仍待试玩。

### 人口增长流程

住房与食物／建筑要求满足 → 移民倒计时 → 远端生成队伍 → 实际导航进据点 → 转为正式居民。出发前条件失效会取消倒计时；已经出发的队伍不因刷新需求而消失。在途人口预留住房，队伍未全部入住前不再派出下一批。

按本局历史最高正式人口选阶段，减员不降低阶段；下一次抽取或刷新使用已解锁阶段。同阶段按权重选组，不意味着每个组都一定可满足。

来源：`Script/population/PopulationManager.gd`、`ImmigrationRules.gd`、`immigration_group.gd`、`Script/unit/game/migrant.gd`、[阶段移民说明](归档/阶段移民与饮食喜好_第一版说明.md)。

### 移民条件是什么

| 条件 | 当前含义 |
| --- | --- |
| 食物 | 按组配置的食物标签合计库存；是门槛检查，不因移民到达额外扣一份门槛食物 |
| 住房 | 必须有可用容量，计入在途预留 |
| 建筑 | 按稳定 ID 判断，必须已建成、未毁坏、未进入拆除 |
| 组参数 | 阶段、权重、人数、到达间隔和居民必带标签 |

现有示例阶段从 0／6／12 人起，包含基础、谷物、肉类及加工食物需求。详细数值见原说明与当前关卡 `.tres`；示例值不是已经验收的最终平衡。

“加工食物需求存在”不等于加工生产链已实现。`processed_food` 是当前资源标签匹配口径，精致食物的最终定义仍待确认。

### 需求刷新与进食

刷新从当前阶段重新抽取，尽量避开上一组；60 游戏秒冷却，暂停冻结、加速同步。刷新尚未出发的倒计时，保留已出发队伍及其出生标签。

居民优先吃喜欢的食物，缺少时回退普通食物。喜好可提供饱腹倍率和临时饥饿减缓；多项效果取较强值、不连乘，同强度可刷新时长。普通进食、休息和驻军进食共享营养效果。当前资料不能证明完整“讨厌食物”系统已实现。

来源：[阶段移民说明](归档/阶段移民与饮食喜好_第一版说明.md)、`Script/unit/UnitBase.gd`、`Script/resource/food_properties.gd`、`Script/trait/trait_data.gd`。

### 配置在哪里

关卡插件“地图与资源 → 移民需求池”配置组、食物、建筑、人数及标签，随关卡保存。住房容量来自建筑配置／功能场景；单位需求参数在单位编辑器；食物营养与标签在资源定义。

关卡使用 `data/levels/LevelFlow_40min_Hard.tres` 等预设，不能为了测试覆盖用户正式配置。建成建筑规则和冷却应由运行逻辑执行，不能只改 HUD 数字。

### 地图与游戏怎样分工

`addons/MapGenerate` 是独立子模块，负责地形轮廓、高度、模型库、植被和通用地表数据。游戏侧 `Script/world/map_generate_runtime.gd` 接入关卡配置、可采集资源、网格、导航和建筑影响。

手动设置、自动生成和模型库各有职责；`cell_size_m` 缩放输出，不修改原模型资源。地图重建、障碍变化和缓存失效不能混为一谈。当前导航变化已合并请求并异步烘焙，不应把“改成异步”再列作未实现任务。

来源：[地图插件 README](../addons/MapGenerate/README.md)、`Script/world/map_generate_runtime.gd::_rebuild_navigation_async()`、[工程约束](../AGENTS.md)。

### 资源和植被

可采集树石由关卡资源条目控制地形权重、簇、精确间距、湿润度、生长与再生。成熟资源阻挡导航；幼苗与成熟的碰撞生命周期不同。再生遵守建筑、蓝图、道路与通道，不能强凑数量。

装饰植被由地图插件生成，种类权重、模型比例、适湿范围与范围外概率各有含义；有限候选不保证目标数量或最终出现比例。游戏迷雾覆盖植被，植被不因此成为视野源。

来源：`Script/world/map_resource_entry.gd`、`map_generate_runtime.gd`、`Script/resource/ResourceBase.gd`、[插件 README](../addons/MapGenerate/README.md)、[历史生长再生记录](归档/历史记录/开发记录_截至2026-10-07.md)。独立森林占格演示仍是实验，不代表正式生成已迁移。

### 昼夜与迷雾

主场景已使用 `StylizedDayNight`；实际是自定义昼夜天空、太阳／月亮、星星和云，而非旧计划要求的静态白天 `ProceduralSkyMaterial`。游戏订阅夜间倍率，白天倍率为 1。独立 `lens_effects` 演示没有接入主游戏。

战争迷雾维护当前视野、探索记录和显示贴图，含树遮挡、树冠表现及对象显隐。当前有角度、像素和对象子节点缓存；不能说刷新已没有 CPU 成本。旧天空 README 尾部“夜间倍率未接入”与其顶部更新矛盾，当前接入以 `Script/main.gd`、[开发记录](归档/历史记录/开发记录_截至2026-10-07.md)和[天空插件说明顶部](../addons/stylized_day_night/README.md)为依据。
