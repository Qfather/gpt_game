# BOSS V0：关卡配置与胜利条件

## 当前可用 BOSS

- 恶魔 BOSS：裂缝阵营，420 生命、18 攻击，带基础震地能力。
- 蜘蛛 BOSS：裂缝阵营，320 生命、13 攻击。
- 两者均使用基础几何体组合模型，`EnemyData.is_boss` 已启用，可在关卡插件裂缝 BOSS 组的候选列表中选择。

## 在关卡编辑器中设置

1. 打开底部“关卡”插件，新建一个怪物组。
2. 将组类型设为“裂缝”，勾选“BOSS组”，组模式建议先选“固定”。
3. 点击“添加单位”，选择“恶魔BOSS”或“蜘蛛BOSS”；固定数量设为 1。
4. 新建出场事件，选择这个怪物组，设置事件名、出场时间和裂缝倒计时，然后保存。
5. 若已有多个裂缝 BOSS 事件，基础出场时间最晚的一个会在时间线中标为“关底BOSS”。时间随机偏移不参与此判断；袭扰 BOSS 会被忽略。
6. 为了便于第一次验证，建议只配置一个裂缝 BOSS 事件。使用随机组时，把该事件的“怪物总数”设置为 1。

## 胜利判定流程

```text
关卡事件到时
  → RiftManager 开启裂缝倒计时
  → 倒计时结束后生成 BOSS（BOSS组固定只开一波）
  → 裂缝阵营的活动单位全部被击败
  → 检查完成事件是否为“基础出场时间最晚的裂缝 BOSS 事件”
      ├─ 否：结束本事件，继续关卡
      └─ 是：GameState 进入 VICTORY、暂停世界、显示胜利界面
```

因此，小 BOSS 被击败不会结束关卡；袭扰 BOSS 被击败也不会触发胜利。只有裂缝时间线中最后一个 BOSS 事件完成后才胜利。若据点先被摧毁，失败状态优先，胜利事件不会覆盖失败。

## 测试建议

1. 先只保留/创建一个裂缝 BOSS 事件，使用恶魔或蜘蛛，固定数量 1，倒计时设短。
2. 开局后确认裂缝提示、BOSS生成、BOSS头顶血条和受伤/死亡反馈。
3. 击败 BOSS 后确认胜利界面出现，暂停状态下“重新开始”仍可点击。
4. 额外验证：把同一时间附近放一个袭扰 BOSS；击败袭扰 BOSS 不应胜利。配置两个裂缝 BOSS 时，先击败较早一个应继续，击败较晚一个才胜利。
