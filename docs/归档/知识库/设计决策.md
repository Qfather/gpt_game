## 已能解释的文档差异

- T0～T3原任务书写“不做抽卡界面”，同日更新已做调试三选一；正式奖励仍未接入。它是范围变化，不是应该删除已有UI。
- 旧城墙文档写石制直接菜单、资源绕障，后续改为木制升级和到场清障；模型尺寸／六形态约定仍有价值。
- 建筑／单位第一版的“后续射箭”和“点击保存才写入”属于阶段记录，后续实现与自动保存取代这些状态。
- 旧综合设计同时包含“维修暂不做”“主线已完成”等跨阶段语句；当前维修、战争迷雾、道路和部分编辑器已有实现。
- 旧天空计划限定白天，现有组件是昼夜；插件README也有尾部旧句与顶部更新不一致，游戏已接夜间视野倍率。
- 营地排查下半段仍写失败／未改源码，顶部已补修复结果。当前归纳采用顶部结果，保留原失败作证据。
- 性能报告在不同玩法、人口、设备、日志设置和顺序阶段下计时，不能把所有数值排成同一版性能曲线。

逐文件替代关系见[文档盘点](文档盘点.md)。这些差异已在知识库解释，不为统一说法重写原始记录。

## 仍要确认的设计问题

1. 正式蓝图奖励何时触发、来自哪里、怎样分池？调试入口不替代正式规则。
2. 加工／精致食物最终定义与生产链是否要进入近期开发？当前只证明标签和需求机制。
3. 模块化建筑是否继续采用旧管线，仓库外是否已有资产或转换成果？现有桥接工具不足以证明全链路。
4. 当前避让是否保持停用，什么实际拥堵体验会触发下一轮调整？已有局部测试没有大规模结论。

这些问题先保留。选到对应任务时再确认，不用为了完成文档整理一次决定全部未来玩法。
