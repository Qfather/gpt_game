## 人口增长流程

住房与食物／建筑要求满足 → 移民倒计时 → 远端生成队伍 → 实际导航进据点 → 转为正式居民。出发前条件失效会取消倒计时；已经出发的队伍不因刷新需求而消失。在途人口预留住房，队伍未全部入住前不再派出下一批。

按本局历史最高正式人口选阶段，减员不降低阶段；下一次抽取或刷新使用已解锁阶段。同阶段按权重选组，不意味着每个组都一定可满足。

来源：`Script/population/PopulationManager.gd`、`ImmigrationRules.gd`、`immigration_group.gd`、`Script/unit/game/migrant.gd`、[阶段移民说明](../阶段移民与饮食喜好_第一版说明.md)。

## 移民条件是什么

| 条件 | 当前含义 |
| --- | --- |
| 食物 | 按组配置的食物标签合计库存；是门槛检查，不因移民到达额外扣一份门槛食物 |
| 住房 | 必须有可用容量，计入在途预留 |
| 建筑 | 按稳定 ID 判断，必须已建成、未毁坏、未进入拆除 |
| 组参数 | 阶段、权重、人数、到达间隔和居民必带标签 |

现有示例阶段从 0／6／12 人起，包含基础、谷物、肉类及加工食物需求。详细数值见原说明与当前关卡 `.tres`；示例值不是已经验收的最终平衡。

“加工食物需求存在”不等于加工生产链已实现。`processed_food` 是当前资源标签匹配口径，精致食物的最终定义仍待确认。

## 需求刷新与进食

刷新从当前阶段重新抽取，尽量避开上一组；60 游戏秒冷却，暂停冻结、加速同步。刷新尚未出发的倒计时，保留已出发队伍及其出生标签。

居民优先吃喜欢的食物，缺少时回退普通食物。喜好可提供饱腹倍率和临时饥饿减缓；多项效果取较强值、不连乘，同强度可刷新时长。普通进食、休息和驻军进食共享营养效果。当前资料不能证明完整“讨厌食物”系统已实现。

来源：[阶段移民说明](../阶段移民与饮食喜好_第一版说明.md)、`Script/unit/UnitBase.gd`、`Script/resource/food_properties.gd`、`Script/trait/trait_data.gd`。

## 配置在哪里

关卡插件“地图与资源 → 移民需求池”配置组、食物、建筑、人数及标签，随关卡保存。住房容量来自建筑配置／功能场景；单位需求参数在单位编辑器；食物营养与标签在资源定义。

关卡使用 `data/levels/LevelFlow_40min_Hard.tres` 等预设，不能为了测试覆盖用户正式配置。建成建筑规则和冷却应由运行逻辑执行，不能只改 HUD 数字。
