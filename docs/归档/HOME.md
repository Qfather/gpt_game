## 怎样判断信息是否可信

- **代码核对**：本轮检查了对应代码或数据入口，不代表已经运行验证。
- **已有验证记录**：原文记录了测试方式和结果，只覆盖当时的布局、版本与断言；本轮没有重跑游戏。
- **用户实测记录**：明确存在用户试玩确认，范围仍受记录限制。
- **计划／待确认**：保留方向和问题，不能作为当前已实现能力或已授权任务。

当前规则以代码、最新明确需求和最新记录交叉核对。发生矛盾时，系统页列出差异；代码现状不自动代表最终设计意图。测试文件存在也不等于测试通过。

## 维护方式

1. 开发时随手追加收件箱；正在做的事情只在当前工作页保留少量条目。
2. 行为改变后更新对应系统页和 README；具体过程、验证与未通过项写开发日志。
3. 长期候选归未来想法；原方案和原始证据在文档盘点中查找。每周再选择下一项任务。

根 README 管启动、操作与当前限制；本首页管导航；系统页管归纳规则；ROADMAP 管长期方向；日志管历史证据。同一段内容不在各页重复抄写。

使用 Obsidian 时可直接打开 `docs` 文件夹，以 `HOME.md` 为入口。本知识库使用普通 Markdown 相对链接，没有插件依赖。代码链接用于回查，部分代码文件需由编辑器或文件管理器打开。
