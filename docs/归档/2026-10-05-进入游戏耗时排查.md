# 2026-10-05：进入游戏耗时排查

本轮为启动性能诊断，未修改正式运行脚本。仪表和缓存对照均位于忽略的 `.godot` 目录。

## 测量方法

- 使用实际 `Scene/main.tscn`，当前关卡配置，40×40 地图、705 个地形格、568 个可采集资源，布局种子固定为 42。
- 使用 Godot 4.7.2、Forward+ / D3D12、GTX 1650，依次启动独立 GPU 测试进程，未并行运行这些测量。
- 记录主场景资源加载、实例化、入树初始化、地图生成完成和随后 `RenderingServer.frame_post_draw` 的时间；使用临时派生脚本细分道路、导航和网格查询。
- 三轮未启用缓存的运行，加一轮临时缓存对照。用户的编辑器和游戏没有关闭。
- 总时间从测试脚本开始计时，包含本轮仪表脚本的加载；不包含 Godot 进程创建前、编辑器保存或资源导入准备。因此它不是完整的 F5 按键到画面出现耗时。

## 已确认的主要开销

| 项目 | 基线测量 |
|---|---:|
| 脚本计时起点到完整地图渲染 | 13.3–15.4 秒 |
| 主场景资源加载 | 1.23–1.37 秒 |
| 主场景实例化 | 0.017–0.018 秒 |
| 地图初始化总计 | 7.16–7.53 秒 |
| 道路预览图初始化 | 3.27–3.31 秒 |
| 资源生成 | 1.36–1.67 秒 |
| 地形数据生成 | 1.00–1.02 秒 |
| 地形模型生成 | 0.88–0.89 秒 |
| 导航构建（含几何收集及烘焙） | 0.087–0.093 秒 |
| 主场景自身 `_ready`（含本轮仪表安装） | 0.16–0.17 秒 |
| 地图完成至首个完整渲染帧 | 3.30–5.15 秒 |

道路和导航是地图总计中的子项，不能将这些行全部相加。地图生成中的帧等待及入树/渲染准备也会影响总时间。

### 道路预览图重复查询地形

生产入口为 `Script/world/road_manager.gd::_refresh_stroke_graph()`：开局对整片 120×120 的 1m 网格建立四向连接。地图实际每个地形格是 3m，同一个地图格对应多个游戏网格，但它们重复读取相同高度与可建造性。

详细一轮：

- 网格高度调用 27,597 次，累计 2,643ms。
- 网格可建造性调用 14,406 次，累计 482ms。
- 道路资源覆盖格计算约 330ms（包含其中部分高度查询，与上述累计项有重叠）。
- 道路图总计 3,266ms。

`Script/world/map_generate_runtime.gd::_get_grid_ground_height()` 每次调用 `WFCHeightField.get_cell_surface_height()`。插件高度计算会反复扫描高度控制点，并进一步计算四个顶点高度；开局地形不变，但计算结果没有复用。

这也是日志里“导航与网格”约 3.4 秒容易误导的原因：实际导航构建约 0.09 秒，大部分来自道路预览图。

### 首帧渲染等待

地图完成后仍有 3.3–5.2 秒等待。测量中，首画面前营地系统累计约 0.01ms、猎物系统约 2.1ms、迷雾刷新约 58ms，无法解释这段数秒等待。

与此同时，Godot 管线编译计数从地图完成时的 mesh=6、其余=0，变为 canvas=4、mesh=6、surface=16、specialization=17。表明首绘制阶段确有渲染管线初始化。当前测量没有分别量化管线编译、资源上传和 GPU 等待，不能把整个等待都直接算作着色器编译。地图约 11,200 个节点也需要首次提交渲染。

## 临时地形缓存对照

仅在临时派生脚本中，按地图格缓存可建造性与高度；保持实际关卡、地图种子、资源数量、地形高度计算与寻路参数。

| 项目 | 未缓存（第三轮） | 临时缓存 |
|---|---:|---:|
| 道路预览图 | 3,266ms | 266ms |
| 高度查询累计 | 2,643ms | 97ms |
| 可建造性查询累计 | 482ms | 68ms |
| 资源覆盖格 | 330ms | 45ms |
| 导航与网格 | 3,359ms | 353ms |
| 地图初始化总计 | 7,528ms | 4,146ms |
| 脚本起点至完整地图渲染 | 13,332ms | 10,834ms |
| 地图完成至渲染帧 | 3,297ms | 3,265ms |

这确认地形结果缓存能消除约 3 秒的道路初始化开销。整段启动时间降低约 2.5 秒；不同运行的首段入树/渲染准备有波动，不应把单轮总时间差作为稳定保证。

正式优化的第一优先级是运行时地形高度及可建造性缓存，地图重建时清空。不要直接在插件编辑器共享的可变高度资源上增加永久缓存而遗漏控制点变更后的失效。之后再独立剖析首帧渲染准备，并处理资源/地形生成。

## 正式优化结果

运行时地形查询已复用地图格世界坐标缓存，并增加地图格可建造性缓存。给 `height_field` 重新赋值时统一清空两份缓存；道路上的动态建筑、资源障碍仍由原有逻辑更新。

实际图形模式三轮复测，道路预览图初始化分别为 327ms、325ms、325ms，相比基线约 3,300ms 减少约 90%。高度查询累计约 111ms，可建造性查询约 113ms，导航与网格整体约 414–421ms。

第二轮地图初始化 4,098ms，脚本起点到完整地图渲染 9,762ms。第一、第三轮整体分别为 20,333ms、18,467ms，主场景初始化、资源生成等其它阶段出现较大波动。道路初始化改善稳定，但整体启动耗时不能承诺固定降到 10 秒；这些额外波动尚未定位。

验证：新增 `Tests/map_terrain_cache_test.gd` 对照原算法，覆盖同格重复查询、负坐标、坡道、阶梯、边界空洞及替换地形后的缓存失效；道路预览动态障碍、道路施工、箭塔高台分配、资源布局和资源再生回归通过。资源布局测试中原来读取旧据点方块网格的断言已改为当前据点点击区域尺寸，保留六格占地检查。已运行实际图形模式并检查开局截图 `.godot/startup-cached-view.png`。

正式复测日志：`.godot/startup-profile-production-cache.out`、`.godot/startup-profile-production-cache-2.out`、`.godot/startup-profile-production-cache-3.out`。这些复测未开启临时仪表的 `--cache-terrain` 实验缓存。

## 第二阶段：资源生成优化

进一步计时发现资源地形权重计算约 452ms；放置资源 1,534 次累计约 463ms，精确边缘间距 3,167 次仅约 20ms，不能把资源生成开销都归为精确碰撞检查。

本轮改动：

1. 先读取各格四角，收集非阶梯平地高度；之后用同一份数据判定相邻崖脚／崖顶，避免为每条相邻边重复读取四角。
2. 保留资源场景中的全部外观候选供编辑，运行时根据原有种子挑选外观，首次为该外观生成只含一个模型的 PackedScene 模板并缓存。后续直接实例化单模型模板；仍按原候选数量消耗随机数，因此模型选择、随机旋转与缩放一致。没有外观候选或只有一个候选的资源沿用直接实例化。

| 测量 | 第二阶段前 | 优化后第 1 轮 | 优化后第 2 轮 |
| --- | ---: | ---: | ---: |
| 资源地形权重 | 452ms | 141ms | 233ms |
| 放置资源累计 | 463ms | 344ms | 476ms |
| 资源生成总计 | 1,415ms | 1,050ms | 1,373ms |
| 地图完成到首个渲染帧 | 3,369ms | 3,140ms | 3,576ms |
| 脚本起点到完整地图渲染 | 10,497ms | 9,818ms | 11,897ms |

资源权重计算有明确改善；第二轮整体其它阶段也变慢，整段启动时间存在波动，不能保证上述单轮总时间差。首帧渲染等待约 3–3.6 秒仍在，本轮没有通过改变画质来掩盖它。

`Tests/resource_visual_cache_test.gd` 对照树／石各 60 个种子，验证模型层级、网格、材质、可见性、随机旋转缩放与碰撞范围，并验证缓存实例的生长。200 次实例化与释放：树木 31.10ms → 6.82ms，石头 35.28ms → 6.46ms（无界面独立测试，不等同于整局启动提升）。

布局种子 42 修改前后均为地形签名 `2242443573`、资源位置签名 `3328991132`，资源数量 520 树／48 石。地形权重、资源再生及受击动画回归通过；已运行实际图形模式并检查开局画面。

日志：`.godot/startup-resource-baseline.out`、`.godot/startup-resource-optimized.out`、`.godot/startup-resource-optimized-2.out`，以及 `.godot/resource-layout-before-stage2.out`／`.godot/resource-layout-after-stage2.out`。

## 第三阶段：悬崖接壤候选实例优化

`Script/world/随机显示自己模型.gd`（原名 `悬崖接壤.gd`）原来为每组创建三个候选，只显示其中一个，另外两个继续常驻。当前关卡统计为 245 组、490 个隐藏模型、980 个隐藏节点，未包含隐藏物理体。

随机选择与缓存逻辑现已统一到 `Script/world/随机显示自己模型.gd`，初版拆出的 `cliff_model_factory.gd` 已移除。游戏运行时向地形生成入口注入该脚本的 `instantiate_model`；首次为所选组合整理只保留选中候选的 PackedScene 模板，后续复用。模板首次构建仍会短暂创建全部候选，缓存命中后只实例化选中模型。仅挂载脚本、执行 `_ready()` 无法避免创建场景中已有的候选；原场景及插件独立预览保留原有三个候选。组合选择沿原节点 ready 顺序消费全局随机数，缓存实例不再次抽签；模型位置、材质覆盖路径及碰撞结构保留。

验证结果：

- 同一阶段实际关卡总节点 11,136 → 10,156；接壤隐藏候选／隐藏节点降至 0。
- `Tests/cliff_model_cache_test.gd` 对照直面、双面、拐角和普通平面共 120 组种子，验证可见模型、材质、变换和后续全局随机序列一致，接壤仅保留一个候选。
- 500 次生成与释放的独立无界面测量：直面 30.66ms → 22.23ms、双面 52.42ms → 35.89ms、拐角 56.96ms → 42.47ms；普通平面 4.67ms → 5.71ms（多一次缓存查找，差约 1ms/500 次）。
- 实际图形模式基线与优化后地形模型阶段为 924ms／933ms，未测到明显整体改善。脚本起点到完整地图渲染为 10,416ms／9,761ms，包含其它阶段波动，不能将整段差值归为此优化收益。
- 资源布局种子 42 的地形签名 `2242443573`、资源位置签名 `3328991132` 与修改前一致，仍为 520 树／48 石；已检查实际开局画面。

本轮主要收益是减少常驻节点，未量化内存字节数或运行帧率收益。日志：`.godot/cliff-variant-inventory.out`、`.godot/cliff-variant-after.out`、`.godot/cliff-model-cache-test.out`、`.godot/startup-cliff-baseline.out`、`.godot/startup-cliff-optimized.out`。
