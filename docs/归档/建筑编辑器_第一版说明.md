# 建筑编辑器第一版

入口为 Godot 编辑器底部的 **“建筑”** 标签，由现有“资源”插件提供。如果更新后尚未出现，重新启用该插件或重开编辑器。

左侧统一列出军营、据点、农场、城门、住宅、伐木场、采石场、剑士营、火把、城墙。选择建筑后，左侧方形窗口展示其外观，右侧编辑参数，点击“保存建筑与专属参数”保存。

| 位置 | 内容 | 保存位置 |
| --- | --- | --- |
| 左侧预览与外观模型 | 自动取景的方形 3D 预览；可拖入 GLB 或 3D 模型场景，留空时使用功能场景的原外观 | BuildingData.model_scene |
| 通用建筑属性 | 名称、统一说明、功能场景、血量、护甲、占地、成本、建造时间、施工人数、旋转／镜像、驻军容量 | `data/buildings/` 下的 BuildingData |
| 建筑专属参数 | 人口容量、训练、工人数与工作范围、农场时间与产粮、军粮总容量、损坏阈值、火把寿命等 | 当前引用的建筑 `.tscn` 场景 |
| 资源仓储 | 添加资源，以下拉菜单选择资源名称，再填写该资源的独立容量；支持删除 | BuildingData.storage_capacities |

## 外观、生命与仓储规则

- Godot 默认资源字段的缩略图依赖资源预览生成与缓存，可能只显示文字。现在独立方形窗口直接渲染模型网格，十种建筑使用相同显示方式；预览不执行建筑生产、岗位注册或导航脚本。
- 外观模型用于替换视觉网格，原功能场景保留建筑脚本、碰撞和岗位位置。外观场景根节点必须是 Node3D，建议使用纯模型场景或 GLB。血条保留，工地沿用施工预览，竣工后应用成品外观。
- 血量统一读取 BuildingData，现有据点 1000、城墙 500、城门 750，其他建筑 300。护甲默认 1，正伤害减去护甲后最低造成 1 点伤害，零或负伤害不扣血。
- 旧“说明”和“功能说明”已经合并为一个“说明”，保留原文字。文字中的容量、时间等仍由人工维护，并非自动数值摘要。
- 仓储每项容量独立计算，不在列表中的资源无法存入。空列表表示不储存；无原仓储组件的普通建筑在配置非空时会添加通用仓储组件。
- 军营仅存食物，除各资源容量外还受专属页的军粮总容量限制。补给会跳过禁存和已满的食物，不会反复搬运被拒绝的资源。
- 已有库存配置迁移后，伐木场仍存 20 木材、采石场 30 石头、农场 50 粮食，据点三种资源各 1000；军营总容量仍为实际场景中的 30。

## 操作注意

- 修改保存在编辑副本中，点击保存才写入文件。切换建筑或刷新会放弃未保存修改，请先保存。
- 稳定 ID 在此入口只读；成本字典使用已有资源 ID，例如 `wood`、`stone`。仓储下拉项读取现有资源定义，新资源保存后重新选择建筑即可更新列表。
- 保存拒绝无效占地、负建造时间、少于一人的施工上限、负成本、非正血量、负护甲／仓储容量以及非 3D 外观场景。
- 专属参数影响所有引用该场景的建筑。同一场景若在 Godot 场景页有未保存修改，请先保存并关闭，避免两处编辑相互覆盖。
- 新参数用于下一次运行或新实例，已经运行的建筑不会自动更新。
- 据点使用 `BaseData.tres` 统一管理，主场景启动时应用该配置，不加入玩家建造菜单。

## 验证与阶段范围

`Tests/building_editor_test.gd` 在带图形设备的编辑器模式验证十种建筑模型渲染、专属字段、场景结构往返、替换模型、资源下拉与容量、血量护甲、隔离修改及保存读回，生成界面截图。测试只向 `.godot/` 写入副本。

`Tests/building_editor_runtime_test.gd` 在真实地图验证保存后的住宅仍提供七人容量，外观替换保留碰撞；据点、普通建筑和资源建筑均按护甲减伤；新增肉类库存只接受十单位；军营遵守军粮限制、补给资源筛选，并在被毁后释放驻军。原人口、耐久和军事回归另行检查。

建筑编辑器第一版仍需用户实际操作确认。单位编辑器、射箭、猎物生成和猎人小屋属于后续阶段。编辑器／游戏退出仍有项目原有的 Flow Graph 和资源释放告警，不把无界面测试作为完整视觉验收。
