# 营地回归失败排查（2026-10-09）

## 修复结果

同日已按用户授权修复：营地资格检查拒绝 `leaving_immigration_base`、`initial_idle_position_pending` 或 `passing_door` 为true的单位，UI可分配名单和实际分配共用这个判断；撤回时旧快照的零碰撞掩码恢复为正常室外掩码3，保留原有非零掩码。

`treasure_assignment_transition_test.gd` 已从三项断言失败变为通过，并增加尚未到达待命点时拒绝分配、实际站位完成后仍可分配、旧零掩码恢复的验证。`treasure_camp_runtime_test.gd` 已通过驻军／巡逻撤回、面板按钮往返、清剿、释放参战单位、发布搬运任务、物资实际入库及营地刷新，退出码0。

旧整链路测试增加真实出门／返程站位等待，保留原断言、清剿600帧及搬运3600帧时限。面板撤回后不能立即重加仍在返程站位的角色：按钮测试期间暂将有效攻击伤害设为0，避免等待返程时自动清剿提前结束营地；重新添加后回到原战斗起点，通过隔离的单位配置设置100点伤害并断言实际生效。此调整分开验证面板往返和清剿，未改变游戏战斗参数。

三兵种真实训练及配方快照、训练进门中断、邻塔训练入口、巡逻编组回归均通过。D3D12有渲染营地整链路也通过、退出码0，已检查实际面板截图。退出仍有既有资源释放告警，不作为本次逻辑修复已解决项。以下保留修复前的排查证据；其中“本轮未修改”及“当前失败”均指排查阶段。

## 结论

原营地测试的四项失败主要来自同一个前置问题：只等待20帧便操作仍在初始出门中的角色，后续旧出门回调继续改变角色位置和状态。只在隔离副本中等待角色实际完成出门、排队及待命站位，保留原断言、布局、600帧清剿时限和3600帧搬运时限，旧营地链路全部断言通过、退出码0。

另外确认了一项需要修复的真实BUG：营地分配接口允许正在训练出门的士兵接受任务，保存出门期间的碰撞掩码0；出门完成恢复碰撞后，再撤回营地任务会把掩码恢复成0，导致角色不再检测建筑、资源、城墙等阻挡。已新增失败回归，本轮未修改营地玩法实现。

## 原四项失败的原因

| 原失败项 | 诊断证据 | 判定 |
| --- | --- | --- |
| 撤回驻军后返回原军营 | 测试强设驻军前，角色仍为 `leaving_immigration_base=true`、`initial_idle_position_pending=true`；撤回后 `is_idle()` 为false，重新安排军营失败 | 测试未满足前置条件；等待真实出门完成后原断言通过 |
| 限时击败全部守卫 | 测试把战士摆到营地，但初始出门尚未结束；旧回调把角色带回据点并重设待命目标，战士随后重新走向营地 | 时间主要消耗在旧出门与重新赶路；等待前置完成后，同样600帧时限通过 |
| 清剿完成释放参战单位 | 检查时守卫未全死，`camp.cleared` 仍为false | 上一项失败的连带结果，不能据此认定释放逻辑单独损坏 |
| 清剿完成发布搬运任务 | 同上；营地只在全部守卫死亡后解锁拾取并发布任务 | 连带结果；等待前置完成后原断言通过，后续实际搬运也通过 |

原条件的快照：战士开始清剿时仍在出门，位置为营地附近 `(19.5, 3, 21)`；100次等待后却位于据点附近 `(4.88, 3, -6.45)`，状态回到待命移动。600次等待约经过604个物理帧、9.99墙钟秒，不能把该段当作从一名已准备好的士兵开始计算的纯战斗时间。

还有一个独立测试配置错误：旧测试写入 `combat_damage=100`，实际攻击却由 `get_attack_damage()` 读取 `base_attack_damage` 及标签效果，运行值仍为10。等待前置完成的对照没有修正这个字段，实际伤害仍为10而整链路通过，因此该错误不是这次四项失败的必要原因，但建议同步修正测试配置，避免误以为已设置100点伤害。

相关实现：`can_accept_treasure_hunt()`、`begin_treasure_hunt()`、`finish_treasure_hunt()`、`try_assign_to_barracks()` 和 `is_idle()` 在 [villager.gd](../Script/unit/game/villager.gd)；真实攻击值在 [UnitBase.gd](../Script/unit/UnitBase.gd)。原测试见 [treasure_camp_runtime_test.gd](../Tests/treasure_camp_runtime_test.gd)。

## 已确认需要修复的游戏BUG

复现路径为实际行走、入屋训练、获得剑士身份、出门过程中分配营地任务，未将角色摆到最终位置或强设训练完成状态：

1. 训练完成时，士兵处于 `state=IDLE`、`passing_door=true`、`current_task=null`、`collision_mask=0`。
2. 营地资格检查返回true；实际添加也成功，`treasure_resume.collision_mask` 保存为0。
3. 出门动画实际完成，实体碰撞掩码正常恢复为3。
4. 撤回营地任务后，恢复保存值0，实体层仍为2但不再检测阻挡。

新增 [treasure_assignment_transition_test.gd](../Tests/treasure_assignment_transition_test.gd)，目前退出码1，明确保留三条失败断言：出门期不应列入可分配名单、接口不应接受分配、撤回不应关闭碰撞。这个退出码表示BUG成功复现，不能写成玩法测试通过。

建议优先修复：营地资格检查拒绝正在出门、进出门排队或初始待命站位中的单位，使UI名单和分配入口共用同一判断；同时核对撤回不能恢复临时出门碰撞状态。应验证合法空闲、驻军、巡逻仍可接受和撤回任务，不能只修测试或强行清空角色过渡标记。
